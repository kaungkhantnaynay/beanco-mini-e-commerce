# Architecture Decision Records

Use this directory for decisions that materially affect architecture, security,
operations, data models, or third-party providers.

Name records sequentially:

```text
0001-short-decision-title.md
0002-next-decision-title.md
```

Each record should contain:

- Status: proposed, accepted, superseded, or rejected
- Date
- Context and constraints
- Decision
- Alternatives considered
- Consequences and follow-up work

Do not use an ADR to bypass approval for a scope or architecture change. Record the
decision after the responsible user or team approves it.
